## Testing Protocol (Read Before Coding Anything)

### How tests work in this project

```
e2e/
  api.e2e.spec.ts        ← API tests (no auth, direct HTTP requests)
  routes.e2e.spec.ts     ← Page load smoke tests (authenticated, uses data-testid)
  auth.setup.ts          ← Auth setup (runs once before other tests)
  auth-page.e2e.spec.ts  ← Login page tests (unauthenticated)
```

**Test runner:** Playwright (`npm run test:e2e`)  
**Full gate:** `npm run build:verify` = `tsc` + `build` + all e2e tests  
**Server mode for tests:** production build served on port 4173, `DISABLE_CRON=1`

### The rule for every feature in this plan

```
IMPLEMENT → ADD data-testid ATTRIBUTES → WRITE TESTS → npm run build:verify → ✅ PASS = DONE
                                                                              ↓ FAIL = FIX, NOT MOVE ON
```

### data-testid naming convention (match what already exists)
```
text-{page}-title        ← page heading (used by routes.e2e.spec.ts)
button-{action}          ← buttons
input-{name}             ← inputs
link-nav-{name}          ← sidebar nav links (kebab-case)
card-{entity}-{id}       ← list item cards
badge-{name}             ← status badges
```

### Adding a new page: required minimum
1. Add `data-testid="text-{page}-title"` to the page heading element
2. Add route entry to `routes.e2e.spec.ts`:
   ```typescript
   { path: "/newpage", selector: '[data-testid="text-newpage-title"]' },
   ```
3. Add nav link with `data-testid="link-nav-{name}"` in `app-sidebar.tsx`
4. Run `npm run build:verify` — the route smoke test must pass

### Adding a new API endpoint: required minimum
Add test to `api.e2e.spec.ts` covering:
- Happy path (200/201 with expected shape)
- Missing required fields (400)
- Non-existent resource (404)

### Where to add unit-level logic tests
Pure functions (e.g. `addThreadNumbering`, `transformText`, `splitIntoThread`)
should be tested inline in the spec files with `test.describe` blocks in `api.e2e.spec.ts`.
No separate unit test framework needed — keep everything in Playwright specs.

## Bug 1 — Thread Numbering (1/N) Missing or Malformed

**Priority:** Critical — affects every thread posted right now  
**Files:** `server/routes.ts`, `server/autopilot.ts`, `server/social/x.ts`

### Problem
Threads generated by AI do not reliably have "1/N", "2/N" per tweet.
The AI is asked to add numbering in some prompts, but it:
- Puts numbers at the start of the hook line (breaks the hook)
- Skips numbering entirely
- Adds them inconsistently across different post types

### Root cause
No post-processing step normalises numbering. The AI controls it, and AI is unreliable
for formatting rules.

### Implementation steps

#### Step B1.1 — Add `addThreadNumbering` utility in `server/routes.ts`
Add this function near the top of `server/routes.ts` (after the imports, before routes):

```typescript
/**
 * Appends "N/total" to the end of each tweet in a multi-tweet thread.
 * Single tweets are returned unchanged.
 * If appending would exceed 280 chars, the tweet body is trimmed to fit.
 */
export function addThreadNumbering(tweets: string[]): string[] {
  if (tweets.length <= 1) return tweets;
  const total = tweets.length;
  return tweets.map((text, i) => {
    const trimmed = text.trim();
    // Already numbered — skip (idempotent)
    if (/\n\n\d+\/\d+\s*$/.test(trimmed)) return trimmed;
    const num = `${i + 1}/${total}`;
    const withNum = `${trimmed}\n\n${num}`;
    if (withNum.length <= 280) return withNum;
    // Trim body to fit within 280
    const maxBody = 280 - num.length - 2; // 2 = "\n\n"
    return `${trimmed.slice(0, maxBody)}\n\n${num}`;
  });
}
```

## Bug 2 — Thread Finisher Not Working as Expected

**Priority:** Critical — CTA tweet not appearing or appearing in wrong position  
**File:** `server/social/x.ts`

### Problem
The `X_THREAD_FINISHER` env var appends a CTA tweet when publishing. Issues:
1. Finisher is appended BEFORE `addThreadNumbering` runs (if ever), so it gets
   a wrong number or no number while others get numbers
2. CTA detection keywords are too narrow (misses many cases)
3. Finisher may exceed 280 chars silently
4. When `targetPlatform === "both"`, finisher is added twice (once per platform call)

### Implementation steps

#### Step B2.1 — Fix publish flow ordering in `server/social/x.ts`

Current broken order:
```
texts → [finisher appended] → post to X
```

Fixed order:
```
texts → [addThreadNumbering] → [finisher appended WITHOUT number] → post to X
```

Replace the current `postContentToX` function body from line 137 with:

```typescript
export async function postContentToX(texts: string[]): Promise<XPublishResult> {
  const rw = await createRwClientFromDb();
  if (!rw) {
    throw new Error(
      "X credentials missing. Set X_API_KEY + X_API_SECRET + X_ACCESS_TOKEN + " +
      "X_ACCESS_TOKEN_SECRET (OAuth 1.0a), or connect X in Settings.",
    );
  }

  let tweets = texts.map(t => t.trim()).filter(Boolean);
  if (tweets.length === 0) throw new Error("No tweet text to post.");

  // Step 1: Apply thread numbering to original content (before finisher)
  // Import addThreadNumbering from routes or a shared util
  tweets = addThreadNumbering(tweets);

  // Step 2: Append finisher AFTER numbering (finisher has no number)
  const finisher = process.env.X_THREAD_FINISHER?.trim();
  if (finisher && tweets.length > 1) {
    const safeFinisher = finisher.slice(0, 275); // hard cap
    const lastTweet = tweets[tweets.length - 1].toLowerCase();
    const ctaPatterns = ["follow", "subscribe", "rt this", "retweet", "share this", "like and", "🔔", "hit follow"];
    const isAlreadyCTA = ctaPatterns.some(p => lastTweet.includes(p));
    if (!isAlreadyCTA) {
      tweets.push(safeFinisher);
    }
  }

  // Step 3: Resolve username (env var first to avoid paid API call)
  let username: string | null = process.env.X_USERNAME || null;
  if (!username) {
    try { username = (await rw.v2.me()).data.username ?? null; }
    catch { /* optional */ }
  }

  // Step 4: Post each tweet in reply chain
  const tweetIds: string[] = [];
  let lastId: string | undefined;
  for (const text of tweets) {
    const body: { text: string; reply?: { in_reply_to_tweet_id: string } } = {
      text: text.slice(0, 280),
    };
    if (lastId) body.reply = { in_reply_to_tweet_id: lastId };
    const sent = await rw.v2.tweet(body);
    const id = sent.data?.id;
    if (!id) throw new Error("X API returned no tweet id.");
    tweetIds.push(id);
    lastId = id;
  }

  const handle = username || "i";
  const urls = tweetIds.map(id => `https://x.com/${handle}/status/${id}`);
  return { tweetIds, urls, username };
}
```

```typescript
async function getBrandSystemPrompt(platform: "x" | "threads" | "linkedin" = "x"): Promise<string> {
  try {
    const profile = await storage.getUserProfile(1);
    const extras: string[] = [];
    if (profile?.niche) extras.push(`Your niche: ${profile.niche}`);
    if (profile?.audienceDescription) extras.push(`Your audience: ${profile.audienceDescription}`);
    if (profile?.brandVoice) extras.push(`Your brand voice: ${profile.brandVoice}`);
    if (profile?.writingStyleNotes) extras.push(`Your writing style: ${profile.writingStyleNotes}`);
    if (profile?.contentGoals) extras.push(`Your content goals: ${profile.contentGoals}`);
    if (profile?.messagingPillars?.length) {
      extras.push(`Your messaging pillars: ${profile.messagingPillars.join(", ")}`);
    }

    const platformAddendum = {
      x: "Platform: X (Twitter). 280 chars/tweet. Punchy hooks. No hashtags in body.",
      threads: "Platform: Threads. 500 chars/post. Conversational, paragraph style. No hashtag spam.",
      linkedin: "Platform: LinkedIn. 3000 chars. Professional but human. Strong hook first line. End with a question.",
    }[platform];

    const brandSection = extras.length > 0
      ? `\n\nUSER BRAND PROFILE (apply to every post you write):\n${extras.join("\n")}`
      : "";

    return `${SYSTEM_PROMPT}${brandSection}\n\n${platformAddendum}`;
  } catch {
    return SYSTEM_PROMPT;
  }
}
```

```typescript
async function generateAutopostDraft(idea: DiscoveredIdea, source: RssSource): Promise<void> {
  const { addThreadNumbering } = await import("./utils/threadUtils");
  const { aiCall, logAiUsage } = await import("./ai/chat");
  const { getBrandSystemPrompt } = await import("./routes"); // or shared util

  const { content, usage, latency } = await aiCall([

    { role: "user", content: `Create a ${source.autopostPostType || "thread"} for X about: "${idea.title}"\n\n${idea.description || ""}\n\nSource: ${idea.sourceUrl || ""}` },
  ]);
  await logAiUsage(usage, latency, "rss_autopost");
  
  const rawTweets = content.split("---").map(t => t.trim()).filter(Boolean);
  const numbered = addThreadNumbering(rawTweets);
  const tweets = numbered.map((content, i) => ({ content, position: i, charCount: content.length }));
  
  await storage.createPost({

    tone: source.autopostTone || "educational",
    targetPlatform: source.autopostPlatform || "x",
    status: "draft",
    pillarId: source.autopostPillarId || null,
    autopilot: false,
    tweets,
  });
  
  // Mark idea as auto-drafted
  await storage.updateDiscoveredIdeaStatus(idea.id, "auto-drafted");
```

## Feature 6 — Post Formatter (Unicode Text Transformer)

**Status:** Not built. 100% frontend — no backend needed.

#### Step 6.1 — Utility `client/src/lib/unicode-formatter.ts`

```typescript
const BOLD_LOWER_START = 0x1D41A;
const BOLD_UPPER_START = 0x1D400;
const ITALIC_LOWER_START = 0x1D44E;
const ITALIC_UPPER_START = 0x1D434;
const MONO_LOWER_START = 0x1D68A;
const MONO_UPPER_START = 0x1D670;

function charOffset(char: string, lowerStart: number, upperStart: number): string {
  const code = char.charCodeAt(0);
  if (code >= 97 && code <= 122) return String.fromCodePoint(lowerStart + code - 97);
  if (code >= 65 && code <= 90)  return String.fromCodePoint(upperStart + code - 65);
  return char;
}

export function toBold(text: string): string {
  return [...text].map(c => charOffset(c, BOLD_LOWER_START, BOLD_UPPER_START)).join("");
}
export function toItalic(text: string): string {
  return [...text].map(c => charOffset(c, ITALIC_LOWER_START, ITALIC_UPPER_START)).join("");
}
export function toMonospace(text: string): string {
  return [...text].map(c => charOffset(c, MONO_LOWER_START, MONO_UPPER_START)).join("");
}
export function toStrikethrough(text: string): string {
  return [...text].map(c => c + "̶").join("");
}

export const FORMATS = { bold: toBold, italic: toItalic, monospace: toMonospace, strikethrough: toStrikethrough } as const;
export type FormatKey = keyof typeof FORMATS;
```

```typescript
import Parser from "rss-parser";
import { storage } from "./storage";
import { addThreadNumbering } from "./utils/threadUtils";
import { aiCall, logAiUsage } from "./ai/chat";
import { getBrandSystemPrompt } from "./routes"; // or shared util

const rssParser = new Parser();

export async function checkYoutubeChannels(): Promise<void> {
  const channels = await storage.getActiveYoutubeChannels();
  for (const channel of channels) {
    await checkChannel(channel).catch(e =>
      console.error(`[youtube-connector] Channel ${channel.channelId} failed:`, e)
    );
  }
}

async function checkChannel(channel: any): Promise<void> {
  const feedUrl = `https://www.youtube.com/feeds/videos.xml?channel_id=${channel.channelId}`;
  const feed = await rssParser.parseURL(feedUrl);
  const latestEntry = feed.items[0];
  if (!latestEntry) return;

  // yt:video:VIDEO_ID format
  const videoId = (latestEntry as any)["yt:videoId"] || latestEntry.id?.split(":").pop();
  if (!videoId || videoId === channel.lastVideoId) return;

  console.log(`[youtube-connector] New video detected: ${latestEntry.title} (${videoId})`);
  await storage.updateYoutubeChannel(channel.id, {
    lastVideoId: videoId,
    lastCheckedAt: new Date(),
  });

  // Generate post
  const systemPrompt = await getBrandSystemPrompt(channel.autopostPlatform || "x");
  const { content, usage, latency } = await aiCall([
    { role: "system", content: systemPrompt },
    { role: "user", content:
      `New YouTube video uploaded: "${latestEntry.title}" by ${channel.channelName}.
URL: https://www.youtube.com/watch?v=${videoId}
Create a compelling ${channel.autopostPostType || "thread"} for X about this video.
Separate tweets with "---". Do NOT add numbering.` },
  ]);
  await logAiUsage(usage, latency, "youtube_connector");

  const rawTweets = content.split("---").map((t: string) => t.trim()).filter(Boolean);
  const numbered = addThreadNumbering(rawTweets);
  const tweets = numbered.map((c, i) => ({ content: c, position: i, charCount: c.length }));

  await storage.createPost({
    postType: channel.autopostPostType || "thread",
    tone: channel.autopostTone || "educational",
    targetPlatform: channel.autopostPlatform || "x",
    status: channel.requireApproval ? "draft" : "scheduled",
    pillarId: channel.autopostPillarId || null,
    autopilot: false,
    tweets,
  });
  console.log(`[youtube-connector] Draft created for video ${videoId}`);
}
```

```typescript
export function splitIntoThread(text: string, charLimit = 280): string[] {
  if (text.length <= charLimit) return [text];
  
  // Split on sentence boundaries (". " or "\n")
  const sentences = text.split(/(?<=[.!?])\s+|\n\n/);
  const tweets: string[] = [];
  let current = "";
  
  for (const sentence of sentences) {
    const candidate = current ? `${current} ${sentence}` : sentence;
    if (candidate.length <= charLimit) {
      current = candidate;
    } else {
      if (current) tweets.push(current.trim());
      current = sentence.length <= charLimit ? sentence : sentence.slice(0, charLimit);
    }
  }
  if (current) tweets.push(current.trim());
  return tweets.filter(Boolean);
}
```

## Deferred Bug — X Articles Are Being Treated Like Tweets (Implement Last)

**Priority:** High, but **deferred** until all current X feature work is complete  
**Why this is a bug:** Article workflows currently collapse into tweet-style output. An X
Article is a different content object (long-form body + richer structure + optional media),
so it should not be generated/saved/published through tweet-only assumptions.

### Product fundamentals to anchor implementation
- **Eligibility gate:** X Articles are available to Premium+ / verified org tiers; we must
  detect account capability and fail gracefully to draft-only if publishing is unavailable.
- **Format distinction:** Articles are long-form and support rich formatting (headings,
  bold/italic, lists, links, embeds/media). This is not equivalent to segmented tweets.
- **Publishing model:** Articles live as article objects on profile/articles surface and can
  be edited/re-published; tweet posting APIs and assumptions should not be reused blindly.
- **Operational fallback:** If article publishing capability check fails, keep the generated
  article draft in-app and optionally produce a companion tweet/thread summary.

### High-impact writing fundamentals (autopilot prompt requirements)
1. Start with a **specific headline + opening hook** that states audience + problem + payoff.
2. Use **scannable structure**: short paragraphs, clear section headings, bullets for steps.
3. Prioritize **evidence and concrete examples** over generic claims.
4. End with a **single CTA** (avoid multi-CTA dilution).
5. Add at least one visual (cover image, chart, or screenshot) when available.
6. Keep voice human: first-person observations, tradeoffs, and nuanced judgment.

### Desired behavior (autopilot-safe)
- Discovery sources (Reddit, RSS/blogs/sites) can still be ranked as today.
- If a candidate is best represented as an **article**, the system should:
  - Generate an article draft in a human narrative style (not thread fragments),
  - Optionally generate/select an image for the article cover,
  - Save as article-type content with correct fields,
  - Post/publish through the article flow, not the tweet flow.
- If content is better as tweet/thread, keep using existing tweet/thread pipelines.
