**Architecture — Provider Interface (Go):**
```go
// All providers implement this interface
type LLMProvider interface {
    Name() string
    GenerateContent(ctx context.Context, req GenerationRequest) (*GenerationResponse, error)
    ListModels(ctx context.Context) ([]Model, error)
    HealthCheck(ctx context.Context) error
}

type GenerationRequest struct {
    SystemPrompt string
    UserPrompt   string
    Model        string
    MaxTokens    int
    Temperature  float64
    TopP         float64
}

type GenerationResponse struct {
    Content      string
    Model        string
    Provider     string
    TokensUsed   TokenUsage
    LatencyMs    int64
}

type TokenUsage struct {
    Input  int
    Output int
    Total  int
}
```

#### 2. Social Media Publishing (X + Threads)

**X (Twitter) Integration — OAuth 2.0 PKCE Flow:**

- Implement X API v2 OAuth 2.0 with PKCE (no client secret needed for public clients)
- OAuth flow:
  1. User clicks "Connect X Account" in Settings
  2. App redirects to `https://twitter.com/i/oauth2/authorize` with PKCE challenge
  3. User authorizes the app
  4. Callback receives auth code → exchange for access token + refresh token
  5. Store tokens encrypted in DB (same encryption as API keys)
  6. Auto-refresh tokens before expiry using refresh token grant
- Required X API v2 scopes: `tweet.read`, `tweet.write`, `users.read`, `offline.access`
- X API v2 endpoints to implement:
  - `POST /2/tweets` — Post a single tweet
  - `POST /2/tweets` with `reply.in_reply_to_tweet_id` — Post thread (chain of replies)
  - `GET /2/users/me` — Fetch connected account info (username, profile pic, follower count)
  - `GET /2/tweets/:id` with `tweet.fields=public_metrics` — Fetch engagement metrics for posted tweets
  - `DELETE /2/tweets/:id` — Delete a posted tweet
- Rate limit handling: implement exponential backoff, respect `x-rate-limit-remaining` headers, queue posts if rate limited
- X API app setup instructions in README:
  1. Go to https://developer.x.com/en/portal/dashboard
  2. Create a project + app
  3. Enable OAuth 2.0 with type "Public" (for PKCE)
  4. Set callback URL to `http://localhost:3000/callback/x` (dev) or production URL
  5. Copy Client ID → paste into ContentForge settings
  6. Note: X Free tier allows 1,500 tweets/month (read), 500 tweets/month (write) — show remaining quota in UI

**Threads (Meta) Integration — OAuth Flow:**

- Implement Meta's Threads API (via Instagram Graph API / Threads Publishing API)
- OAuth flow:
  1. User clicks "Connect Threads Account" in Settings
  2. Redirect to Meta OAuth: `https://www.threads.net/oauth/authorize`
  3. User authorizes → callback with auth code
  4. Exchange code for long-lived access token (60 days)
  5. Store encrypted, auto-refresh before expiry
- Required Threads API scopes: `threads_basic`, `threads_content_publish`, `threads_read_replies`, `threads_manage_insights`
- Threads API endpoints to implement:
  - `POST /{user-id}/threads` → Create media container (text post)
  - `POST /{user-id}/threads_publish` → Publish the container
  - For threads/carousels: create multiple containers, then publish as carousel
  - `GET /{thread-id}/insights` → Fetch engagement metrics (views, likes, replies, reposts)
  - `GET /{user-id}/threads` → List published threads
- Character limit for Threads: 500 characters per post (validate in UI before posting)
- Threads API app setup instructions in README:
  1. Go to https://developers.facebook.com/
  2. Create a Meta app with "Threads API" use case
  3. Add Threads Login product
  4. Set callback URL
  5. Submit for App Review (required for publishing)
  6. Copy App ID + App Secret → paste into ContentForge settings

**Cross-Platform Publishing Features:**

### Database Schema (PostgreSQL)
```sql
-- AI Provider configurations
CREATE TABLE ai_providers (
  id SERIAL PRIMARY KEY,
  provider_type VARCHAR(50) NOT NULL, -- anthropic, openai, gemini, mistral, cohere, groq, together, perplexity, deepseek, xai, ollama, lmstudio, localai, vllm, llamacpp, oobabooga, custom_openai
  display_name VARCHAR(100) NOT NULL,
  is_local BOOLEAN DEFAULT FALSE,
  base_url VARCHAR(500), -- for local providers or custom endpoints
  api_key_encrypted TEXT, -- encrypted API key for cloud providers
  default_model VARCHAR(100),
  is_enabled BOOLEAN DEFAULT TRUE,
  is_default BOOLEAN DEFAULT FALSE, -- only one can be default
  config_json JSONB, -- extra provider-specific config
  created_at TIMESTAMPTZ DEFAULT NOW(),
  updated_at TIMESTAMPTZ DEFAULT NOW()
);

-- Connected social accounts
CREATE TABLE social_accounts (
  id SERIAL PRIMARY KEY,
  platform VARCHAR(20) NOT NULL, -- x, threads
  platform_user_id VARCHAR(100),
  username VARCHAR(100),
  display_name VARCHAR(200),
  profile_image_url TEXT,
  access_token_encrypted TEXT NOT NULL,
  refresh_token_encrypted TEXT,
  token_expires_at TIMESTAMPTZ,
  scopes TEXT, -- comma-separated granted scopes
  is_connected BOOLEAN DEFAULT TRUE,
  last_synced_at TIMESTAMPTZ,
  metadata_json JSONB, -- follower count, rate limits, etc.
  created_at TIMESTAMPTZ DEFAULT NOW(),
  updated_at TIMESTAMPTZ DEFAULT NOW()
);

-- Content pillars
CREATE TABLE pillars (
  id SERIAL PRIMARY KEY,
  name VARCHAR(100) NOT NULL,
  description TEXT,
  color VARCHAR(7) -- hex color for UI
);

-- Content posts
CREATE TABLE posts (
  id SERIAL PRIMARY KEY,
  pillar_id INTEGER REFERENCES pillars(id),
  post_type VARCHAR(20) NOT NULL, -- tweet, thread, poll, quote_template, hot_take
  tone VARCHAR(20),
  target_platform VARCHAR(20) DEFAULT 'both', -- x, threads, both
  status VARCHAR(20) DEFAULT 'draft', -- draft, ready, scheduled, publishing, posted, failed
  scheduled_at TIMESTAMPTZ,
  posted_at TIMESTAMPTZ,
  ai_provider_id INTEGER REFERENCES ai_providers(id), -- which provider generated this
  ai_model_used VARCHAR(100),
  created_at TIMESTAMPTZ DEFAULT NOW(),
  updated_at TIMESTAMPTZ DEFAULT NOW()
);

-- Individual tweets/posts within a post (supports threads)
CREATE TABLE tweets (
  id SERIAL PRIMARY KEY,
  post_id INTEGER REFERENCES posts(id) ON DELETE CASCADE,
  position INTEGER NOT NULL, -- order in thread
  content TEXT NOT NULL,
  char_count INTEGER,
  created_at TIMESTAMPTZ DEFAULT NOW()
);

-- Published post references (links posts to platform-specific IDs)
CREATE TABLE published_posts (
  id SERIAL PRIMARY KEY,
  post_id INTEGER REFERENCES posts(id) ON DELETE CASCADE,
  social_account_id INTEGER REFERENCES social_accounts(id),
  platform VARCHAR(20) NOT NULL, -- x, threads
  platform_post_id VARCHAR(100), -- tweet ID or thread ID
  platform_url TEXT, -- direct link to the post
  published_at TIMESTAMPTZ DEFAULT NOW(),
  status VARCHAR(20) DEFAULT 'success', -- success, failed, deleted
  error_message TEXT,
  metadata_json JSONB -- raw API response
);

-- Publish log (every attempt, success or failure)
CREATE TABLE publish_log (
  id SERIAL PRIMARY KEY,
  post_id INTEGER REFERENCES posts(id),
  platform VARCHAR(20) NOT NULL,
  action VARCHAR(20) NOT NULL, -- publish, delete, retry
  status VARCHAR(20) NOT NULL, -- success, failed, rate_limited
  error_message TEXT,
  api_response_json JSONB,
  created_at TIMESTAMPTZ DEFAULT NOW()
);

-- Content ideas bank
CREATE TABLE ideas (
  id SERIAL PRIMARY KEY,
  title VARCHAR(280) NOT NULL,
  notes TEXT,
  pillar_id INTEGER REFERENCES pillars(id),
  is_expanded BOOLEAN DEFAULT FALSE,
  created_at TIMESTAMPTZ DEFAULT NOW()
);

-- Templates
CREATE TABLE templates (
  id SERIAL PRIMARY KEY,
  name VARCHAR(200) NOT NULL,
  pattern TEXT NOT NULL,
  post_type VARCHAR(20),
  pillar_id INTEGER REFERENCES pillars(id)
);

-- Analytics (auto-fetched + manual)
CREATE TABLE analytics (
  id SERIAL PRIMARY KEY,
  post_id INTEGER REFERENCES posts(id),
  platform VARCHAR(20), -- x, threads, manual
  impressions INTEGER DEFAULT 0,
  likes INTEGER DEFAULT 0,
  retweets INTEGER DEFAULT 0, -- or reposts for Threads
  replies INTEGER DEFAULT 0,
  quotes INTEGER DEFAULT 0,
  bookmarks INTEGER DEFAULT 0,
  profile_visits INTEGER DEFAULT 0,
  views INTEGER DEFAULT 0, -- Threads-specific
  source VARCHAR(20) DEFAULT 'manual', -- api_auto, manual
  recorded_at TIMESTAMPTZ DEFAULT NOW()
);

-- Follower tracking (auto-fetched from connected accounts)
CREATE TABLE follower_snapshots (
  id SERIAL PRIMARY KEY,
  platform VARCHAR(20) NOT NULL,
  count INTEGER NOT NULL,
  recorded_at TIMESTAMPTZ DEFAULT NOW()
);

-- AI token usage tracking
CREATE TABLE ai_usage_log (
  id SERIAL PRIMARY KEY,
  provider_id INTEGER REFERENCES ai_providers(id),
  provider_type VARCHAR(50) NOT NULL,
  model VARCHAR(100) NOT NULL,
  input_tokens INTEGER,
  output_tokens INTEGER,
  total_tokens INTEGER,
  latency_ms INTEGER,
  estimated_cost_usd DECIMAL(10, 6), -- approximate cost
  feature VARCHAR(50), -- generate, expand_idea, fill_template, hooks, hashtags
  created_at TIMESTAMPTZ DEFAULT NOW()
);
```
